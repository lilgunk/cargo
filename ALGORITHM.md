# Алгоритм укладки (LoadOpti)

Код: `src/algorithm/packCargo.ts` (эвристика), `verifyPacking.ts` (независимая проверка), `computePlan.ts` + `packWorker.ts` (расчёт в Web Worker).

Результат — **эвристика**: хорошая, проверенная укладка, но не доказанно наилучшая. Задача трёхмерной упаковки NP-трудная, поэтому слово «оптимально» в интерфейсе не используется.

## Модель

- Кузов — прямоугольный параллелепипед L × W × H (мм). Начало координат — передний левый угол пола у перегородки кабины; X → к задним дверям, Y → к правой стенке, Z → вверх.
- Колёсные арки — параллелепипеды у обеих стенок (`startX…endX`, выступ `intrusionPerSide`, высота `heightFromFloor`). Верх арки — опорная поверхность.
- Груз — параллелепипеды: размеры, масса, количество, правило поворота (`none` / `horizontal` / `any`), `stackable` (можно ли ставить сверху), `floorOnly` (только на пол — паллеты, тяжёлое).
- Паллеты в форме: EUR 1200×800, EUR ½ 800×600, промышленная 1200×1000; вводится общая высота с паллетой; паллета всегда `floorOnly`, поворот только 90° в горизонтали.

## Ограничения (проверяются для каждой позиции)

1. Груз целиком внутри кузова.
2. Нет пересечений с арками и другим грузом (касание гранями разрешено).
3. Порядок загрузки: нельзя задвинуть груз *под* уже стоящий.
4. Поворот — только разрешённый правилом.
5. Сечение груза проходит в задние двери (`rearDoor`).
6. Опора: площадь контакта снизу ≥ 75 % основания (пол, арки, другие грузы).
7. Устойчивость: центр основания над выпуклой оболочкой площадок опоры.
8. На груз с `stackable = false` ничего не ставится.
9. Груз `floorOnly` стоит только на полу.
10. Сумма масс ≤ грузоподъёмность.

## Поиск

**Extreme Points** (Crainic, Perboli, Tadei, 2008): после каждого размещённого груза его углы проецируются на ближайшие грани; эти точки — кандидаты для следующих грузов. Арки считаются заранее поставленными телами. Отличие от статьи: сами углы тоже сохраняются (иначе теряется позиция «прямо на коробке»).

Для каждой единицы груза (в порядке сортировки) перебираются точки × разрешённые повороты; первая допустимая позиция по выбранному правилу принимается.

**Группы при сортировке:** груз «только на пол» идёт первым (ему нужен пол); в части вариантов груз «не ставить сверху» идёт последним и ставится **как можно выше** — на него всё равно ничего не поставят, поэтому на полу он занимал бы целую колонну.

**Портфель из 58 детерминированных вариантов**, берётся лучший:

| Группа | Вариантов | Идея |
|---|---|---|
| 5 сортировок × 4 правила позиции | 20 | сортировка: объём, площадь основания, высота, длинная сторона, масса; позиция: «сначала пол», «от кабины», «вдоль стенки», «максимальный контакт» (Lodi, Martello, Vigo) |
| то же + «не ставить сверху» последним и наверх | 20 | хрупкий/нештабелируемый груз — поверх стопок |
| единый поворот × 3 правила (+ «не ставить сверху» наверх) | 18 | все единицы одного типа в одном положении → ровные ряды |

Лучший = больше объёма внутри → больше штук → больше массы; при равенстве: меньше пола занято грузом «не ставить сверху» → меньше пустоты над ним → короче занятая длина кузова (больше свободного пола у дверей) → ниже центр масс.

**Порядок загрузки (шаги).** Поиск ставит груз в своём порядке (например, сначала весь пол). Шаги для человека перестраиваются отдельно (`loadingSequence`): каждый следующий шаг — груз, ближайший к кабине, у которого уже стоят все опоры (затем ниже, затем левее). Так стенка у кабины собирается снизу доверху, потом следующая — без возвратов «через» уже уложенный груз. Верификатор проверяет, что опора всегда грузится раньше.

Если груз не влез, называется причина: `TOO_LARGE`, `DOOR_OPENING`, `PAYLOAD_EXCEEDED`, `NO_SPACE`, `NO_FLOOR_SPACE`, `NOT_STACKABLE`, `INSUFFICIENT_SUPPORT`, `UNSTABLE` — с подсказкой, что сделать.

## Проверка

- `verifyPacking` заново проверяет все ограничения готового плана, не используя код поиска. В интерфейсе: «Sprawdzono: 0 naruszeń».
- Тесты (`npm test`, 35 шт.): сценарии с арками, все причины, негабарит, паллеты, `floorOnly`; property-тесты fast-check на случайных фургонах и наборах (каждый план — 0 нарушений, каждая единица учтена ровно один раз); детерминизм.
- **Эталон**: для одинаковых коробок в пустом кузове лучшая «решётка» известна заранее. Тест требует, чтобы алгоритм клал не меньше.

## Ограничения модели (честно для защиты)

- Только параллелепипеды, только оси кузова (без укладки по диагонали).
- Дверь: груз должен проходить в том положении, в котором стоит (поворот внутри кузова не моделируется — осторожная оценка).
- Арки — параллелепипеды; размеры арок и дверей в каталоге приблизительные (помечены в `mockData.ts`).
- Нет расчёта нагрузки на оси, крепления груза, хрупкости по массе сверху.
